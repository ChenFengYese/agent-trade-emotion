`--output` 以不可覆盖方式保存本次 G1 验收报告和内容摘要；证据不足写成 `WAIT_DATA`，只有 `PASS` 才能交给协议 finalizer。M0B 协议同时绑定 G1 policy ID/SHA-256 与 `g1_report_sha256`，并冻结状态分类器 ID/摘要、每状态 100 个有效 episode、总计 600 个、5 folds 与 300 秒 embargo。任一预声明状态样本不足、总有效 episode 不足、出现未分类/未知状态，或 G1 报告不通过/被篡改/摘要不匹配，报告都只记录 `INCONCLUSIVE/WAIT_DATA`，不会训练基线；CLI 也不能覆盖冻结 folds/embargo。

在且仅在取得新的 `PASS` G1 报告后，可由报告中列出的合格 collection 生成研究 feature bundle。命令要求传入的 Evidence Store 根目录与报告中的合格根目录完全一致；每个 collection 使用新的簿和 episode 状态机重放，不会跨断点延续状态，并产生不可覆盖的 feature artifact 与 provenance manifest：

```bash
python3 -m trade_system build-features-g1-bundle \
  --data-dir .runtime/forward-a \
  --data-dir .runtime/forward-b \
  --g1-report artifacts/g1.bundle.v1.json \
  --episode-policy config/episode_policy.v1.json \
  --output artifacts/features.g1.v1.ndjson \
  --manifest artifacts/features.g1.v1.manifest.json \
  --bundle-id features.g1.v1
```

构建器重验每个 collection 的 audit/replay 摘要和分段封存状态，并给 event/episode 加入证据命名空间；报告、目录或 collection 摘要任一不匹配都会拒绝。还必须先从 [episode_policy.frozen.template.json](/Users/wt/Documents/agent-trade-emotion/config/episode_policy.frozen.template.json) 创建冻结 episode policy：它把 trigger feature、方向压力阈值、episode cooldown 和状态机阈值绑定到 feature version。没有该 policy，G1 bundle 不会使用开发期“首个 snapshot 即观察”的兼容逻辑；`build-features` 在未传 `--episode-policy` 时仅保留该兼容路径给合成/开发 artifact，绝不能作为 G1 输入。当前草稿 G1 报告不能运行 bundle 命令。

feature bundle 不会自动把临时阈值变成样本。先从 [research_action_policy.frozen.template.json](/Users/wt/Documents/agent-trade-emotion/config/research_action_policy.frozen.template.json) 创建并冻结研究专用 action-policy，绑定 exact feature-bundle manifest；它只产生反事实市场路径候选动作，明确假设 `COUNTERFACTUAL_FILLED_FOR_MARKET_LABEL_ONLY`，不代表实际成交或下单：

```bash
python3 -m trade_system validate-action-policy --policy config/research_action_policy.v1.json
python3 -m trade_system build-actions-g1-bundle \
  --features artifacts/features.g1.v1.ndjson \
  --feature-manifest artifacts/features.g1.v1.manifest.json \
  --action-policy config/research_action_policy.v1.json \
  --output artifacts/actions.g1.v1.ndjson \
  --manifest artifacts/actions.g1.v1.manifest.json \
  --actions-id actions.g1.v1
```

每条 action 必须带有来自 bundle manifest 的 `evidence_id`；`label-actions-g1-bundle` 校验 action manifest 后，只读取同一 ID 的价格路径，避免相邻或重叠 collection 影响 barrier 顺序。它同样产生新的不可覆盖 label artifact 与 manifest：

```bash
python3 -m trade_system label-actions-g1-bundle \
  --actions artifacts/actions.g1.v1.ndjson \
  --action-manifest artifacts/actions.g1.v1.manifest.json \
  --features artifacts/features.g1.v1.ndjson \
  --feature-manifest artifacts/features.g1.v1.manifest.json \
  --output artifacts/labels.g1.v1.ndjson \
  --manifest artifacts/labels.g1.v1.manifest.json \
  --labels-id labels.g1.v1
```

通用 `label-actions` 保留给开发/合成路径；它不替代上述 G1 provenance 链。未知 `evidence_id`、feature 内容篡改或 bundle manifest 摘要不符都会拒绝。

随后用同一冻结分类器派生 state-bound label artifact；该命令会校验 label manifest、复制 G1 绑定并生成新的不可覆盖 state-label manifest。冻结研究必须显式传入这一 manifest，且其 G1 报告与分类器摘要必须与协议一致：

```bash
python3 -m trade_system assign-states-g1-bundle \
```
