# 项目核心目标重载与研究优先级

> 日期：2026-08-02
> 状态：项目目标与研究优先级入口；不是新的 Core 理论版本，不修改任何冻结实验，也不授予 paper/live 权限
> 当前理论权威：`CORE_TRADING_THEORY_v2_1.md`，证据等级仍为 E0

## 1. 核心结论

本项目的核心不是建设 Agent 集群、聊天 transport、通用编排平台或更多 schema。

本项目真正要研究和交付的是：

> **从点时可得的市场数据出发，持续维护多时间尺度、可证伪的竞争路径；在风险、成本、监督条件和不确定性约束下，把路径判断转换为持有、分批建仓、加减仓、退出与重新进入，并用未见的连续市场结果检验其预测价值、决策忠实度和成本后经济价值。**

Agent 是其中处理难以完全固定化的市场解释、路径竞争和可行域内选择的组件；确定性系统负责数据时点、算术、风险、权限、状态提交和执行安全。Agent 拓扑是否为单 Agent、条件 Critic 或集群，是次级工程与消融问题，不是项目成功标准。

## 2. 当前权威层级必须分开

| 层级 | 当前地位 | 可以支持什么 | 不能支持什么 |
|---|---|---|---|
| Core v2.1 基础理论 | 当前权威，E0 | 数据/推理纪律、D/L/C/F/R/K、吸收—响应、PIT、风险与证据阶梯 | 尚不能证明预测有效、成本后 alpha 或稳定盈利 |
| Core v2.1 的窄 V1 | BTCUSDT 极值后吸收—修复/反转 baseline | 作为有限、可证伪的旧策略对照 | 明示不交易趋势延续，不能代表当前扩展产品目标 |
| Core §16 动态路径方法 | 上位 E0 方法 | 有限竞争机制、可变路径、UNKNOWN、路径与动作分层 | 不是持续持仓政策，也没有自行获得新增风险权限 |
| Continuous Strategic Decision Policy | V2 challenger，未晋升 Core | 把动态路径编译为持续战略、CORE/TACTICAL、重入和滚动计划 | 尚无未见连续市场证据，关键参数仍未知 |
| Theory Paper V1 | 已终止历史 paper 事故样本 | 暴露状态、退出、重入、评价和时钟故障 | 不能证明原理论成功或失败，不能继续运行 |

最重要的冲突是：**原窄 V1 主动放弃趋势延续，而用户当前目标要求在反弹后继续比较延续、回撤、衰竭和失败，并管理核心仓位。** 这不是调一个阈值能够解决的实现小错，而是旧策略范围与新产品目标的明确错配。正确做法是保留 V1 为 baseline，以独立 challenger 检验扩展政策，而不是后见修改 V1。

## 3. 当前项目的用户结果与必要需求

### 3.1 市场分析结果

每个决策时点必须形成：

1. 实际获得的数据、数据截止时间、来源、质量和适用时间尺度；
2. 获取不到的数据及其影响，缺失不得补零或伪造；
3. 基于已得数据对缺失状态作有标签的有限推论；
4. 同时保留多条可竞争路径，而不是强行选择单一故事；
5. 每条路径的支持、软反证、硬失效、下一验证项和到期条件；
6. 新数据只更新上一状态，不能每轮从当前快照重新开始。

#### 分析指标与数据探索自由

Agent 不应被 D/L/C/F/R/K 或当前预计算字段限制为封闭指标集合。只要满足点时可得、来源可追溯、公式可复算、质量明确和调用成本合理，Agent 可以按市场状态主动请求并组合更多辅助观测，例如：

- Bollinger Bands、bandwidth、`%B` 和 squeeze/expansion；
- session、rolling、anchored 或 event VWAP；
- ATR、realized volatility、波动分位数；
- EMA/MA、ADX、效率比、结构斜率；
- volume profile、成交密集区和相对成交量；
- taker-flow/CVD proxy、盘口失衡、spread、深度和冲击；
- OI、funding、basis、拥挤和跨市场相对强弱；
- 事件时间、新闻元数据和其他合规公开数据。

这些对象是辅助观测，不是预设交易信号。系统不为每个指标编写一条“达到 X 就买卖”的硬规则，也不要求所有指标每轮都出现。Agent 应说明所选指标解决哪个辨别问题、适用哪个时间尺度、改变哪条路径及其局限；无增量或重复信息可直接忽略。

当前 V1 已经按闭合 K 线计算 Bollinger 上下轨并交给分析层；最近 500 笔 `aggTrades` 也计算了 recent-window VWAP，但该 VWAP 没有被传入 Agent 的 `MeasurementSnapshot`，且不等于 session/anchored VWAP。最小改进应先修复这种“已有观测未透传”的问题，再按实际研究价值增补指标，不另建指标专用平台。

### 3.2 多时间尺度治理结果

- 高时间尺度维护战略方向、市场阶段与硬失效条件；
- 中时间尺度更新路径、阶段和风险强弱；
- 低时间尺度优化入场、执行和局部风险；
- 低时间尺度只有取得明确升级依据后才能影响战略状态；
- 风险减仓、战术退出和观点失效必须是不同状态转换；
- 战略复核时钟、执行时钟和 scheduler 唤醒时钟必须分离。

### 3.3 路径—收益—风险—仓位结果

每个有效机会需要同时比较失败、正常反弹、趋势延续、衰竭和 UNKNOWN 路径，并至少输出：

- 当前账户最坏损失与总风险预算；
- 已使用、预留和剩余风险；
- 原仓与新增仓的独立风险；
- 每个候选动作的目标空间、成本、滑点/跳空压力和净盈亏比；
- 盈亏平衡概率门槛；未校准时不得伪造精确胜率或 EV；
- 初始假说仓、确认仓和趋势仓的事前触发、失效、到期与取消条件；
- 当前动作对下一复核点可行行动集合的影响。

首仓较小只能表示保留后续风险额度，不能让“以后再加”停留在自由文本。加仓必须是预注册路径的状态转换，同时重新计算全部 lot 共同失败时的组合损失。

### 3.4 持仓与恢复结果

- lot 必须具有 CORE 或 TACTICAL 角色；HEDGE 在独立合同前不启用；
- TACTICAL 达到目标不能自动清除 CORE 或关闭战略 episode；
- 固定目标、风险退出和战略失效必须分开；
- 未失效时全平必须同时创建重新进入义务、条件和最迟复核时间；
- 空仓不是零成本终态，应记录合格比较政策下的机会差，但不得记入实际亏损；
- 每次只执行滚动计划的第一步，下一轮依据新数据继续更新。

### 3.5 Agent 自主权结果

Agent 应在不可变安全边界内拥有足够动态权力：

- 提出和比较有限竞争机制与路径；
- 解释难以固定化的新闻、结构、量价、流动性与跨市场关系；
- 提议动态几何、CORE/TACTICAL 管理、分批动作与重新进入；
- 在确定性内核给出的真实可行集合中选择并说明依据；
- 保留冲突、UNKNOWN 和反对意见。

Agent 不得自行修改事实、风险上限、前视边界、校准资格、账户状态、权限或历史状态。确定性系统也不得用“谨慎”或默认空仓代替市场判断，更不得静默删除本来可行的持有、加仓或重入候选。

约束采用三档，而不是条条硬编码：

| 档位 | 内容 | 处理方式 |
|---|---|---|
| 硬边界 | 前视、伪造/补零、账户最大风险、极端损失、杠杆/保证金、保护失效、陈旧/冲突数据、交易权限、账户不一致和停机 | 确定性拒绝或停止 |
| 软边界 | 常用时间尺度角色、候选指标、机制库、动作解释、审查提示和复杂度预算 | Agent 可基于证据偏离，但必须说明 |
| 自由实验区 | 新指标组合、竞争路径、动态几何、分批仓位方案、止盈/跟踪/重入候选及复盘假说 | 离线实验中允许主动探索和比较 |

“积极参与”不等于强迫交易或提高换手率。它表示：当存在合格可行动作和可接受账户风险时，Agent 必须实际比较并选择，而不能用“市场不确定、等待确认、谨慎观察”作为无成本默认答案。`ABSTAIN` 必须对应具体数据否决、硬风险、负的保守效用或无法区分的 UNKNOWN；连续 ABSTAIN 应触发机会成本和可行集合审查。

### 3.6 无人值守结果

策略必须适配休息和无法持续盯盘：

- 已保护核心仓可在注册的最坏损失内继续；
- 只有机器可明确表达且同步注册保护的条件动作才能无人值守执行；
- 无法控制跳空、流动性或消息风险时调整风险，不自动改写观点；
- barrier 应由事件/执行规则处理，不能等下一次 Agent 心跳才发现。

## 4. 理论体系的正确结构

### 4.1 认识论与数据纪律

唯一合法链条是：

```text
点时原始事实
→ 可复算测量
→ 带不确定性的状态推断
→ 有限竞争机制与路径
→ 未来情景/路径结果
→ 成本与风险约束下的候选动作
→ 仓位和执行
→ 分层结果评价
```

必须持续区分 `FACT / MEASURE / INFERENCE / HYPOTHESIS / FORECAST / POLICY / RISK`。公开数据不能直接识别真实心理、参与者身份、开平仓意图或完整强平量；所有缺失、静默和代理限制保留为 UNKNOWN。

### 4.2 市场机制理论

核心五因子是：

- `D`：方向压力；
- `L`：杠杆变化；
- `C`：拥挤；
- `F`：已观测强制去杠杆；
- `R`：流动性韧性；
- `K`：跨场、事件、宏观、期权、链上及其他上下文。

核心命题不是“极值必然反转”，而是：主动压力是否仍产生边际价格冲击、对手方流动性是否持续吸收并恢复、这种关系是否完成方向响应。

最小竞争机制族包括：`CONTINUATION`、`ABSORPTION_REVERSAL`、`RANGE`、`LIQUIDATION_CASCADE_OR_LIQUIDITY_VACUUM`、`EVENT_REPRICING`、`ARTIFACT` 和 `OTHER`。机制可共存，不能把同一底层数据重复计权，也不能用 Agent 故事替代可观察证据。

### 4.3 路径与时间理论

- 路径是可变长度、部分有序、可以跳过或重复预注册里程碑的过程；
- 路径只根据当时已观察前缀更新；
- 支持、软反证、硬失效与到期是不同事件；
- 新证据改变 belief，不自动反手或清仓；
- 市场时间尺度具有角色，不进行简单多数投票。

### 4.4 决策政策理论

这是此前最薄弱、当前最重要的理论增量：

```text
持续战略状态
+ 多路径情景
+ 账户风险预算
+ 分段仓位计划
+ 当前价边际盈亏比
+ 监督/离线约束
+ 机会成本比较
→ 滚动动作选择
```

优化目标不是“当轮最安全”或“胜率最高”，而是：在硬风险和执行约束内，提高成本后的长期期望、主要路径捕获和风险调整结果，同时惩罚无依据退出、无义务空仓和重入不对称。

### 4.5 证据与变更治理

- E0 理论/合同；E1 数据质量与确定性重放；E2 锁定样本外；E3 shadow/paper；E4 小资金 canary；E5 生产观察；
- 理论、预测、决策政策、执行和收益证据不能互相替代；
- SNDK/HYPE 已知案例只能用于事故诊断和提出 challenger，不能选择参数或证明有效；
- 新理论变更一次只改一类问题，并在新的未见窗口检验；
- 负结果、ABSTAIN 和简化理论都可以是合格研究结论。

## 6. 当前 V2 已经解决与尚未解决的区别

### 已在设计或 E0 机械层处理

- 持久战略状态、CORE/TACTICAL、重入、动态几何、风险预算、监督状态等对象已有设计和部分代码；
- PIT、事件链、write-once、权限隔离和离线执行 deny 有机械保护；
- V1 事故已只读审计，后见边界清楚；
- 旧集群实验已证明部分结构化审查覆盖可以提高；
- E0B 失败已定位为聊天内 full-packet transport 与长生命周期总控不兼容。

### 尚未解决，且才是核心成败项

1. D/L/C/F/R/K 与竞争路径是否在合格未见数据上具有预测增量；
2. 持久战略政策是否能在连续市场序列中真实避免状态失忆和空仓吸收；
3. CORE/TACTICAL、分段加仓、目标后延续、退出和重入是否改善风险调整结果；
4. 路径盈亏、剩余风险和边际 RR 是否能稳定转化为客观仓位动作；
5. Agent 是否会利用动态能力产生有价值的动作差异，而非只写更完整解释；
6. 无人值守、barrier、漏槽和复核时钟能否保持同一战略语义；
7. 所有关键参数仍未校准：核心比例、tranche、延续门、trailing、重入规模、机会成本权重和 review 窗口；
8. 当前仍无 E1/E2 市场有效性证据，无新的 V2 paper 权限，更无 live 权限。

因此，142 个 schema、功能测试通过或集群输出完整，都不能把上述问题标成已解决。

## 7. 本轮研究必须回答的问题

本轮主问题应重置为：

> **在同一组点时市场输入、相同风险预算、成本模型和监督条件下，持续战略决策政策相对于静态 V1，能否更忠实地维护有效假说，并改善路径捕获、重入及时性和风险调整经济结果？**

分解为五个可证伪问题：

1. `State continuity`：下一轮强制读取上一 accepted state 后，是否消除无依据 PHI 重置、观点/仓位分裂和义务丢失？
2. `Path-to-position`：多路径、总风险、边际 RR 和预留 tranche 是否产生与市场状态一致的 HOLD/ADD/REDUCE/EXIT/REENTER 差异？
3. `Exit symmetry`：退出和重入是否具有对称证据门，空仓是否不再成为无限期吸收状态？
4. `Sequential utility`：相对于同风险静态 V1，动态政策的成本后收益、回撤、尾部风险、路径捕获和机会差是否改善，或至少没有用更大风险换取表面收益？
5. `Agent incremental value`：在确定性内核相同的条件下，单个动态 Strategy Agent 是否优于简单确定性政策；只有该问题先得到可区分结果，才检验 Blind Critic 或集群的边际价值。

## 8. 当前最合适的研究顺序

### P0：冻结并运行最小连续动态基线

- 使用新的、未被正式 Agent 读取的连续窗口；
- 当前权威市场 profile 优先使用 BTCUSDT，SNDK/HYPE 只作已见事故诊断；
- 每个周期读取上一 state head，处理一个真实连续状态转换；
- 默认只调用一个无记忆 Strategy Agent；长期记忆只在结构化状态库；
- 确定性内核计算每个候选动作的风险、成本、边际 RR、组合最坏损失和监督可行性；
- 允许 `WAIT/HOLD_CORE/OPEN_CORE/ADD_CONFIRMATION/ADD_TREND/REDUCE_TACTICAL/PARTIAL_TAKE_PROFIT/EXIT_WITH_REENTRY/REENTER_CORE/INVALIDATE_AND_EXIT` 中符合当前研究权限的动作；
- 未获 ADD 权限时仍可做反事实候选和评价，但不得把它冒充可执行授权；
- 完整走完连续序列后才读取 outcome 并评价，不按中途结果修规则。

每轮 Agent 可以在冻结数据时点内按需请求额外公共观测或指标计算；请求、输入窗口、公式版本、结果和 UNKNOWN 均进入审计，但不要求事前枚举所有可能使用的指标。只有需要进入正式评分或稳定政策的指标，才在下一版本中冻结其公式和作用范围。

### P1：比较决策政策，而不是比较文风

至少保留：

1. 静态 V1 baseline；
2. 持久状态 + CORE/TACTICAL + 重入的确定性最小政策；
3. 同一可行集合上的单 Agent 动态政策。

比较预测/状态、动作忠实、实际损益、成本、回撤、路径捕获和机会成本。不得只比较挑战覆盖率、字段完整率、Agent 一致率或输出长度。

### P2：仅在有动作差异后检验 Critic

Blind Critic 只在全平、战略失效、显著加仓、重入、风险预算压力等高影响转换中按预注册条件触发。只有有益干预多于有害干预、硬错误不增加且经济 guardrail 不恶化，才保留 Critic。固定每轮四 Agent 的完整集群降级为离线研究插件。

### P3：市场证据晋级

完成数据质量与确定性重放后，再进行 walk-forward、校准、同 cohort 成本后比较和一次性 holdout。只有 E2 合格后才另行讨论新的 V2 paper；paper、canary 和 live 均需新的独立授权。

## 9. 本轮实验的最低验收

实验完成不能再定义为“32/32 Agent packet 被传完”。最低验收应是：

1. 一个新的连续未见窗口从 genesis 到 terminal 完整运行；
2. 每轮只使用当时可得数据并消费上一 accepted state；
3. 没有战略状态、lot 角色、review/reentry 义务或风险预算静默丢失；
4. 每个动作都能追溯到路径、风险、成本、监督条件和可行集合；
5. 静态 V1、确定性持续政策和单 Agent 动态政策使用相同数据、风险与成本边界；
6. 实际损益、未实现损益、费用、funding UNKNOWN、基准收益和机会差分账；
7. 评价至少覆盖多 horizon、最大回撤、尾部、路径捕获、空仓持续和重入延迟；
8. 结果可以是支持、失败或不确定，但不能因 transport 或总控上下文耗尽而没有市场研究结果；
9. 任何拓扑结论必须来自动作或经济差异，不能来自语言覆盖；
10. 结论仍只属于相应 E0/E1/E2 层级，不越级声称盈利或实盘就绪。

## 10. 明确停止的偏离方向

在上述最小连续实验完成前，停止把下列事项作为主线：

- 新建 Agent 集群 transport successor；
- 扩张角色数量、schema 数、receipt 数或通用插件平台；
- 继续修复已失败关闭的 E0B；
- 用更多提示词要求 Agent “更大胆”；
- 用 SNDK/HYPE 已知上涨调核心比例、加仓阈值或 trailing 参数；
- 用功能测试、合成 PASS、paper 无报错或 Agent 报告完整度替代市场结果；
- 恢复 automation、paper/live 或接入账户。

只有直接阻塞 P0 连续动态基线的最小工程问题才应进入实施。

## 13. 纠偏后的最小研究边界

先前的模块表、事件流和 `FeatureFunctionRegistry` 不是当前 P0。它们在市场研究尚未成立时过早规定了系统形态，并被实际实现成“固定指标摘要 + 固定三路径 + 预筛动作集合 + Agent 排序”。该实现已经在 seen-V1 和 OKX 连续结果中失败，不再保留为推荐设计。

下一基线只保留以下职责边界：

1. **Agent 负责市场研究**：读取上一 accepted strategic state 和当时可得资料，自主识别需要补取的公开数据，分析多时间尺度结构、情绪与参与行为代理，构造两条以上可证伪竞争路径，并比较持有、试探建仓、加仓、减仓、退出、重入与等待；
2. **确定性代码负责验证与提交**：校验 `available_at <= decision_at`、来源和公式，复算风险、杠杆、保证金、成本和组合最坏损失，明确返回具体 veto，再原子提交状态、lot、账本与复核义务；
3. **风险内核不能代替策略**：它只能删除硬边界上不可行的动作，不能用固定指标阈值、固定交易几何或“谨慎”预先压缩 Agent 的市场判断；
4. **缺失不等于停止研究**：缺失保持 `UNKNOWN`，同时允许 Agent 提出最小公开数据请求；无法取得时保留有标签的多路径推论，不得把推论冒充事实；
5. **空仓有机会成本**：`WAIT/ABSTAIN` 必须说明相对其他可行动作的效用、数据缺口或具体风险 veto，并携带下一复核条件；长期空仓、延迟重入和未使用风险预算都是被评价的结果；
6. **工程只在重复计算出现后沉淀**：先用 V1 历史记录完成可审查的逐时点市场分析和连续仓位方案，再把已证明重复、稳定且直接影响研究结果的计算抽成最小代码；不先写第三个 runner。

现行 `seen_v1_diagnostic` 与 `continuous_experiment` 的应用代码、CLI 和专用测试退役；九份冻结配置保留原始字节作为只读历史合同，其历史 artifact 继续作为负面证据。公开数据适配、点时质量检查、战略状态、风险、成本、账本和内容存储继续保留。任何新实现都必须先证明 Agent 实际看到了情绪/行为证据、产生了竞争路径和至少一个与确定性占位政策可区分的仓位选择，才有资格进入新的连续未见实验。
