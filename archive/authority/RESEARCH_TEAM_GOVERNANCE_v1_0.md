# MSTA-HED 研究团队治理 v1.0

状态：`E0_P0_RESEARCH_GOVERNANCE_CANDIDATE`

本文件只治理研究任务、工件、复核和升级，不授予数据获取、回测、paper、
部署或交易权限。当前权限以
`config/sol_decision.research-system-reconstruction.v1.json` 为准。

## 1. 组织原则

研究团队不采用固定人数或固定角色表。每个阶段只保留能够产生不同工件、
独立证据或对抗视角的最小角色集合。

完整协作链为：

```text
问题定义
→ 依赖分解
→ 独立研究
→ 交叉复核
→ 冲突登记与区分测试
→ 统一整合
→ 独立验收
→ 阶段门裁决
```

新增、删除、重命名或并行调用 Agent 不会扩大当前阶段权限。任何 Agent 都
不能因模型能力、任务数量或历史成功而自授下一阶段权限。

## 2. 动态角色库

### 2.1 程序路线与阶段门负责人

- 角色 ID：`PROGRAM_ROUTE_GOVERNOR`
- 默认模型：`gpt-5.6-sol-ultra`
- 生命周期：按需
- 职责：首次路线设计、完整阶段门、实质路线阻塞、同根因两轮未关闭、理论
  简化/否定、冻结权威或 holdout 冲突。
- 禁止：日常编码、普通测试修复、持续行情监控。

### 2.2 研究负责人

- 角色 ID：`RESEARCH_PROGRAM_LEAD`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：当前阶段持续存在
- 职责：定义问题、依赖、输出、验收、角色组合；整合事实报告；维护任务 DAG；
  形成阶段候选但不自批。
- 禁止：用个人判断覆盖异议；修改冻结权威；自授阶段通过。

### 2.3 理论与机制挑战者

- 角色 ID：`THEORY_MECHANISM_CHALLENGER`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：理论或假说存在未闭合链路时
- 职责：检查概念、前提、因果、边界、替代解释、可证伪性和机制库；维护优先
  假说队列。

### 2.4 状态与测量建模者

- 角色 ID：`STATE_MEASUREMENT_MODELER`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：存在测量合同设计或修订时
- 职责：把语义对象转化为变量、窗口、时钟、公式、状态和未知语义；不设定
  无来源的精确常数。

### 2.5 数据来源权威审计者

- 角色 ID：`SOURCE_AUTHORITY_AUDITOR`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：数据发现、准入和来源变化时
- 职责：检查官方/原始身份、许可、覆盖、修订、点时语义、断档和替代来源。
- 当前限制：只发现文档；不下载市场行、不使用认证或付费访问。

### 2.6 实验设计与反证者

- 角色 ID：`FALSIFICATION_EXPERIMENT_DESIGNER`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：假说准备进入数据阶段前
- 职责：冻结机会宇宙、对照、标签、功效、成本、敏感性、停止规则和错误归因；
  主动寻找反例、泄漏和更简单基线。

### 2.7 合同与验证器构建者

- 角色 ID：`CONTRACT_SCHEMA_BUILDER`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：存在结构化工件时
- 职责：实现严格 schema、规范化、纯 total validator、合成夹具和确定性测试。
- 禁止：把候选对象提供的 digest、trust root、source identity 或 acceptance
  当作外部权威；接受自己的候选。

### 2.8 独立对抗验证者

- 角色 ID：`INDEPENDENT_ADVERSARIAL_VALIDATOR`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：权威、准入、时钟、holdout 和阶段候选的必需角色
- 职责：不使用构建者的 fixture builder 或成功路径 oracle，独立改变字段类型、
  ID、时钟、别名、空值、digest、权限和依赖，复现 fail-closed 行为。

### 2.9 版本与证据管理员

- 角色 ID：`VERSION_EVIDENCE_CURATOR`
- 默认模型：`gpt-5.6-terra-high`
- 生命周期：每个阶段收束时
- 职责：统一术语、记录物理 SHA-256、版本关系、负面结果、争议、修改原因、
  未解决问题和 claim boundary。

## 3. 角色增删规则

只有满足至少一项才新增角色：

- 产生独立、可验收的新工件；
- 需要与构建者分权；
- 能检查不同数据、前提或方法；
- 能关闭高风险依赖；
- 能用低成本区分当前争议。

满足以下任一项则暂停或合并角色：

- 任务已完成；
- 产出与其他角色重复且没有独立性；
- 当前阶段未授权；
- 连续输出缺少证据、超范围或无法复现；
- 额外并行会造成定义漂移或锚定偏差。

低质量 Agent 的处置不是让更多 Agent 重做全部工作，而是：

1. 缩小其输入和唯一输出；
2. 绑定字段、证据和验收格式；
3. 不允许其改核心定义；
4. 对高风险输出增加独立对抗复核；
5. 两轮同根因未关闭时停止继续消耗并升级。

## 4. 统一任务合同

每项任务在分配前必须记录：

| 字段 | 含义 |
| --- | --- |
| `task_id` | 唯一任务 ID |
| `research_question` | 当前要区分的问题 |
| `scope_in` | 允许读取/产生的内容 |
| `scope_out` | 明确禁止内容 |
| `input_identities` | 路径、版本、SHA-256 |
| `definitions` | 必须沿用的概念和变量 |
| `dependencies` | 前置任务 ID |
| `role_id` | 执行角色 |
| `deliverables` | 唯一输出 |
| `acceptance` | 可执行验收 |
| `claim_boundary` | 最大允许声明 |
| `stop_conditions` | 何时停止 |
| `escalation` | 何时交给 Sol |

Agent 输出统一包含：

1. 研究问题；
2. 已知事实；
3. 数据或文档来源；
4. 前提假设；
5. 方法与可审计推导摘要；
6. 主要结论；
7. 反例、冲突与不确定性；
8. 修改建议；
9. 下一项区分测试；
10. 输入/输出 SHA、命令、退出码和声明边界。

不要求输出不可审计的内部思维过程；必须保留的是第三方能复算的变量、公式、
关键步骤、证据映射和参数理由。

## 5. 并行与独立性

可以并行：

- 理论一致性审计与来源权威审计；
- 对同一关键公式进行两路独立复核；
- 来源发现与测量对象建模；
- 构建者实现与独立审查者准备攻击清单。

必须串行：

- 权威路线冻结后才能设计数据获取；
- 原始数据准入后才能运行 adapter；
- replay/PIT 合格后才能构建特征和标签；
- 机会、标签、成本和 chronology 冻结后才能回测；
- 候选冻结后才能打开一次性 holdout；
- E2 不能自动触发 E3。

对关键理论、关键数据语义和关键公式，至少有两路独立视角。但两路使用同一
数据、同一前提或同一代码时，不构成独立证据。

独立复核阶段不预先共享最终结论。可以共享统一定义、输入身份和验收标准，
但不能让第二路只验证第一路的叙述。

## 6. 冲突裁决

冲突不通过投票解决。研究负责人依次比较：

1. 来源权威等级；
2. 文件完整性和点时适用性；
3. 前提是否相同；
4. 变量与样本口径是否相同；
5. 方法是否适用；
6. 推导是否完整；
7. 是否存在隐藏变量、泄漏或选择性样本；
8. 是否能设计低成本区分测试。

结果只能是：

- `RESOLVED_BY_DEFINITION`；
- `RESOLVED_BY_HIGHER_AUTHORITY`；
- `RESOLVED_BY_REPRODUCTION`；
- `SPLIT_SCOPE`；
- `DISCRIMINATING_TEST_REQUIRED`；
- `UNRESOLVED_DISPUTE_POOL`。

未解决冲突进入争议登记表，不能以模糊措辞合并为共识。

## 7. 假说治理

弱证据或无直接证据的假说：

- 不删除；
- 不写成事实；
- 若能产生可观测预测，优先进入验证队列；
- 若尚不能测量，先进入测量设计而非回测；
- 若风险高或能解锁多个模块，提高优先级；
- 若只增加叙事、不产生区分测试，保持潜伏。

假说失败：

1. 冻结输入、版本、结果和负面证据；
2. 判断数据量与质量是否足以判定；
3. 归类主要错误；
4. 只允许一个局部变化；
5. 创建新版本与新 chronology；
6. 使用未见数据复测；
7. 保留旧版本及失败原因。

禁止：

- 看到结果后改变 cohort、label、horizon、cost 或 comparator；
- 重用已打开 holdout；
- 增加相关指标来挽救分数；
- 删除负面 trial；
- 把数据/合同缺陷解释成市场支持或市场反证。

## 9. 阶段验收分权

三个主体必须分离：

- 构建者：产生候选；
- 独立验证者：攻击并报告；
- 阶段门负责人：接受、返工、等待、简化、否定或停止。

本地测试通过、JSON 可解析、多个 Agent 结论相似、或文档数量增加，都不能
自动完成 P0。即使 P0 通过，也不会自动授权 D0。

## 10. 事实汇报标准

每轮事实报告必须列出：

- cwd、branch、HEAD、worktree 状态；
- 实际读取和修改的路径；
- 物理 SHA-256；
- 精确命令和退出码；
- 通过/失败的验收项；
- 根因与未关闭风险；
- 未执行的测试；
- 最大允许声明；
- 下一依赖与权限边界。

“可运行”只表示相应程序在指定环境运行；“合成测试通过”只表示合同对合成
案例闭合；二者都不是市场有效、盈利或可交易证明。

## 11. 升级与停止

调用 Sol ultra：

- 本轮首次路线设计；
- P0、D0、D1、D2、D3、E2、E3 等完整阶段候选完成；
- 同一根因经过两轮 Terra high 仍未关闭；
- 要改变冻结理论、权威、chronology、holdout、资金或交易边界；
- 证据充分的假说失败，需要实质简化、否定或路线变化。

不调用 Sol：

- 普通文档、schema、类型、命名和局部测试问题；
- 不改变含义或权限的可逆实现选择。

立即停止当前动作：

- 需要读取或修改活动 Application Support 根；
- 需要复活旧 active-G1 或终止 P1A；
- 需要下载市场数据、使用凭据、购买数据；
- 需要 adapter、回测、paper、部署或交易但未获相应门；
- 候选试图自授权；
- 看到 outcome 后试图修改冻结研究合同。
