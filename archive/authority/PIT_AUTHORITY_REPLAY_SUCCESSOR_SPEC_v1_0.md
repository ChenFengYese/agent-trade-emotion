## 1. 要解决的真实问题

当前核心理论把交易系统定义为：

```text
多周期市场状态
→ 有限路径假说
→ 证据更新
→ 条件触发
→ 风险约束
→ 执行管理
→ 反馈校准
```

这条方法论是决策层骨架，但它只有在输入满足“当时确实可知”时才可验证。若历史数据后来被修订、归档发布时间被误当成事件时间、缺失值被补零、聚合 K 线的高低点被提前看到，或者重复数据产生第二次作用，则再严密的假说和风险逻辑也会得到虚假的历史优势。

因此，PITAR1 不预测市场，也不替代状态、假说或决策引擎。它补齐其前置证据层：

> 每一个进入未来研究系统的事实，都必须能回答“字节来自哪里、谁授权、何时可知、属于哪个修订、缺口是什么、以什么顺序产生作用、事后能否复现”。

PITAR1 的程序问题是：

> 能否在不读取未来信息、不覆盖历史状态、不把未知伪装成零的前提下，把外部原始字节转换为可追溯、可重放、可比较的点时事件？

## 2. 与当前系统的差距

当前工作区已有事件、回放、数据验收与历史诊断模块，它们可以作为工程事实参考，但不能证明 PITAR1 的点时权威。已确认的主要差距是：

1. 缺少逐行的 `event_time / published_at / received_at / ingested_at / admission_validated_at` 五时钟合同。
2. 缺少 `logical_id / revision_id / supersedes_revision_id / operation / revision_ordinal / revision_fork_id` 的完整修订链。
3. 缺少原始字节偏移或成员身份、压缩对象与解压成员的独立摘要。
4. 缺少领域分离且前后链接的准入与回放回执。
5. 重复、同身份异载荷、修订分叉和乱序到达没有统一的失败关闭语义。
6. 市场不活跃、来源中断、获取失败、序列缺口、计划不发布、删失、未知和隔离没有被严格区分。
7. 现有聚合回放不足以证明双障碍先后顺序，也不足以证明 MFE/MAE 未进入策略输入。
8. 已有历史窗口和活动包具有不可变隔离边界，不能被重新命名为未见校准或留出数据。

PITAR1 采取独立新合同与新验证器，不修改、导入或包装既有实现。

## 3. 五层证据边界

交易理论中的事实、推断、假说、决策和执行必须与数据权威再做一次正交分层：

| 层 | PITAR1 问题 | 可进入的内容 | 禁止内容 |
| --- | --- | --- | --- |
| 原始权威 | 字节与来源是否被外部固定 | 字节摘要、长度、来源、条款、方案、证明、tip | 候选自称有效 |
| 点时准入 | 该版本何时真实可知 | 五时钟、`available_at`、修订、覆盖状态 | 用事件时间代替可得时间 |
| 规范化 | 如何无损变成类型记录 | 字段、单位、序列、原始谱系 | 特征、标签、因果或主体意图 |
| 回放 | 当时系统看到什么 | 点时排序、幂等、修订可见性、回执链 | 最新修订回填、未来完整 K 线 |
| 研究比较 | 策略是否获得相同信息 | 相同事件、分母、成本、风险与歧义规则 | 用结果信息评分或选择策略 |

这五层不能互相授权。E0 合同正确不等于数据有效；数据有效不等于市场假说有效；回放正确不等于策略有正期望。

## 4. 外部权威包

### 4.1 候选不能自证

每个未来准入对象必须同时匹配验证器外部固定的五类权威：

1. 来源权威：来源 ID、等级、所有者、来源合同与条款摘要。
2. 物理对象权威：对象 ID、方案 ID、原始摘要、长度、容器摘要、成员摘要与成员 ID。
3. 变换权威：schema、transform、parser 的 ID 与摘要。
4. 覆盖证明权威：证明 ID、摘要与证明类型。
5. tip 权威：tip ID、摘要、提交时间和有效区间。

候选中的同名字段只是待比对声明。候选改变声明、重新计算自己的摘要或同时提交一套新的“外部权威”，均不能使其有效。

### 4.2 原始字节规则

- 原始字节由调用者显式提供。
- 对象以 SHA-256 内容寻址，写入后不可覆盖。
- `payload_sha256` 必须等于实际提供的字节摘要。
- `raw_byte_length` 必须等于实际字节长度。
- 零字节对象的唯一正确摘要为  
  `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855`。
- 压缩容器和解压成员分别记录摘要，不允许混用。
- 更正对象只能追加为新对象和新修订，不能原位覆盖。

## 5. 点时语义

### 5.1 五个知识时钟

| 时钟 | 含义 |
| --- | --- |
| `event_time` | 市场事件或观测所指向的发生时间；不证明系统已知 |
| `published_at` | 来源对该精确修订的权威发布时间；不确定时必须显式未知 |
| `received_at` | 授权获取过程完整观察到精确字节的最早时间 |
| `ingested_at` | 字节被持久保存并完成物理摘要的时间 |
| `admission_validated_at` | 纯准入验证器对精确字节与外部权威完成验证的时间 |

保守可得时间固定为：

```text
available_at =
max(
  verified published_at when applicable,
  received_at,
  ingested_at,
  admission_validated_at
)
```

`event_time`、归档目录日期、bar open、bar close 本身和当前最新修订时间都不能替代 `available_at`。

若精确发布时间或收件时间不能成立，只能：

- 延后可得性；
- 标为批量归档收件边界；
- 标为未知或删失；
- 暂停受影响 lane。

任何不确定性都不能让证据变得更早。

### 5.2 点时选择

决策时点 `decision_at` 只能看到：

```text
available_at <= decision_at
```

之后到达的更正、撤回、墓碑或恢复记录只能从自己的 `available_at` 开始生效，不能重写早期回放结果。

## 6. 修订、重复、冲突和缺口

### 6.1 修订链

一个逻辑事实可以具有多个修订，但必须满足：

- 初始修订 ordinal 为 `0`，operation 为 `INITIAL`，没有 supersedes。
- 后续修订 ordinal 每次加 `1`，并指向前一个 revision ID。
- 同一链保持相同 `logical_id`。
- 修订链无环、只追加、可完整审计。
- 相同 ordinal 与相同父修订出现两个不同子修订时，视为 fork conflict，隔离并暂停。

### 6.2 重复和冲突

- 同一身份与同一载荷的精确重复：幂等，无第二次作用。
- 同一身份但载荷不同：隔离对象、保留证据、暂停对应 lane。
- 乱序到达：保留真实时钟，按可得时间回放；不得按事件时间重排可见性。

### 6.3 覆盖状态

以下状态必须保持不同：

- `CONTINUOUS_OBSERVED`
- `MARKET_INACTIVE_PROVEN`
- `SEQUENCE_GAP`
- `SOURCE_OUTAGE`
- `ACQUISITION_FAILURE`
- `SCHEDULED_NON_PUBLICATION`
- `CENSORED_OBSERVATION`
- `UNKNOWN_COVERAGE`
- `QUARANTINED`

静默不等于零，也不等于无交易。禁止补零、前向填充和插值。未知、ABSTAIN、隔离和删失机会仍保留在机会分母内。

## 7. 未来适配器合同

适配器未来只能接收：

```text
explicit request
+ external D1 admission receipt
+ explicitly supplied admitted raw bytes
```

并输出类型记录、覆盖事件、隔离事件和领域分离回执。纯适配器不得访问：

- 网络；
- 文件系统发现；
- 环境变量；
- 系统时间；
- 随机数；
- 子进程。

适配器不得产生：

- 参与者意图或因果标签；
- 特征或结果标签；
- 概率、效用、预测；
- 仓位、订单、权限；
- 最新修订回填；
- 不同产品或标的身份合并。

当前只有接口合同和合成语义验证，没有适配器实现，也没有 D2 执行权限。

## 8. 确定性回放

未来回放顺序固定为：

```text
(available_at, source_sequence, event_id)
```

`source_sequence` 必须是来源原生序号，或显式命名的本地收件 ordinal。它不能由事件时间或未来信息推导。

确定性条件：

1. 相同准入输入、相同代码和相同配置得到相同记录、顺序、状态转换和回执。
2. 精确重复没有第二次作用。
3. 更正以新事件追加。
4. 每份回放回执绑定前一回执、准入对象集合、适配器版本、配置、事件区间、数量和状态转换摘要。
5. 回执链断裂、摘要不匹配或重复身份均失败关闭。

### 8.1 聚合 K 线和双障碍

- OHLC 高低点只有在精确 bar close 且完成准入后才可见。
- 若同一无序聚合 K 线同时触及上下障碍，且没有更细粒度的已准入来源，结果必须是 `AMBIGUOUS_OR_CENSORED`。
- 不允许假定更有利的障碍先触发。
- MFE 和 MAE 只在结果期结束后作为诊断，不得成为策略输入。

## 9. D3 轨迹与 E2 公平比较边界

D3 未来最多生成点时开发轨迹数据集和回执，不进行评分、排名、选择、回测或盈利判断。

预登记策略恰为：

1. `DYNAMIC_MULTI_PATH`
2. `FROZEN_ENTRY_STATIC_EXIT`
3. `SINGLE_PATH`
4. `NO_TRADE`

公平比较必须保证：

- 四个策略接收相同的已准入点时事件；
- 使用相同机会分母；
- 使用相同时序、手续费、滑点、资金费率、风险预算、流动性和障碍歧义规则；
- `NO_TRADE` 仍保留每个合格机会；
- 任何策略都不能读取 MFE、MAE、未来完整 bar、最新修订回填或其他策略的未来决策。

轨迹记录的是过程，不是成绩：图和路径修订次数、leader 切换、决策延迟、订单动作、成本、尾部损失、风险越界、覆盖/未知/删失状态以及结果后的 MFE/MAE。

任何真实数据评分、统计比较、校准、回测、留出检验或盈利评估均属于 E2，必须另有明确阶段决定。

## 10. 时间窗口隔离

时间角色按 UTC 半开区间定义，首次请求、对象列表、字节访问、下载尝试、外部提供对象检查，或对象存在性、大小、schema、覆盖元数据发现，都会永久消耗该窗口的角色。

固定规则：

- 已见工程窗口不能改成校准或一次性留出。
- 失败或部分访问仍可能消耗角色。
- 未来校准与留出窗口必须在首次访问前冻结且互不重叠。
- 2025 年 1 月和 2 月的既有窗口保持永久已见。
- 活动包时间范围和 Application Support 根目录与 PITAR1 完全隔离。
- alias、symlink、替代根目录或角色改名不能绕过隔离。

## 12. E0 纯验证器

`trade_system/pit_authority_replay_contract_v1.py` 的公共验证函数只接收调用者显式参数。它：

- 精确要求六份合同，不依赖文档顺序，拒绝重复或额外路径；
- 拒绝重复 JSON key、非有限数字、未知顶层字段和错误类型；
- 重算每份合同的领域分离规范摘要，并与验证器外部固定摘要比较；
- 比对外部路线、来源、对象、schema、transform、parser、proof 和 tip 权威；
- 验证真实提供的字节、长度、零字节摘要、五时钟和回执；
- 验证修订、分叉、重复、冲突、缺口、可见性和排序；
- 验证时间窗口角色锁；
- 验证适配接口、回执链和双障碍歧义；
- 验证四策略同信息、同分母、同成本、同风险；
- 验证 D3 轨迹字段但不评分；
- 对任意错误形状返回结构化 `REJECT`，不把异常泄漏为权限。

其正向状态最多是 `VALID_E0_CANDIDATE` 或 `VALID_E0_SYNTHETIC_FIXTURE`。这两个状态都不等于接受。

### P0：E0 接受后的 D0 前置

只有在以下事实全部冻结后，才可提交新的 D0 激活决定：

- 公共、免费、无需认证并满足适用条款；
- 精确来源、标的、产品、schema 与时间窗口；
- 精确对象 URL、大小、逐对象 checksum 与成本；
- 精确发布/收件/修订/缺口语义；
- 资源 cap、磁盘下限、隔离路径和终止条件；
- 窗口在首次访问前冻结。

任一项未知即继续 `WAIT_DATA`，不得为推进而下载。

### 后续关闭阶段

- D1：精确原始对象准入；
- D2：离线适配与确定性回放；
- D3：点时开发轨迹数据集，不评分；
- E2：预登记真实比较、校准或一次性留出；
- E3：paper 或 testnet；
- 部署与真实交易。

每个阶段均关闭，必须有自己的精确外部决定和白名单。前一阶段通过不会自动授权下一阶段。

## 16. 验收条件与证据等级

E0 候选本地可审查要求：

1. 精确工作区、分支、HEAD 与路线摘要一致。
2. 只新增十三个白名单文件。
3. JSON 合同和报告均有可复算的领域分离规范摘要。
4. 验证器不访问文件、网络、环境、系统时间、随机数或子进程。
5. 干净候选、合成语义与 P0 对抗测试全部通过。
6. 来源发现没有获取数据行，九来源均保留真实未知。
7. D0 候选非执行且权限为 `DENIED`。
8. 所有输出维持 `ABSTAIN / 0`。

本阶段允许的最大结论：

> PITAR1 的 E0 合同和合成失败关闭语义在本地测试中形成了可复核候选；官方来源发现仍为 WAIT_DATA，且没有建立数据、点时回放、市场、预测、概率、收益、paper、部署或交易有效性。

禁止把下列事物互相等同：

- 本地测试通过 ≠ 外部阶段接受；
- 合同闭合 ≠ D0 数据可用；
- 文档官方 ≠ 精确对象具有点时权威；
- 合成回放正确 ≠ 真实回放正确；
- 真实回放正确 ≠ 策略有效；
- 历史正收益 ≠ 样本外正期望；
- paper ≠ 可部署或可交易。

## 17. 最终方法论

PITAR1 将当前理论的数据前提压缩为以下固定链路：

```text
外部固定来源与条款
→ 精确对象与原始字节
→ 五时钟保守可得性
→ 修订/重复/冲突/缺口分类
→ 纯规范化与完整谱系
→ 按 available_at 的确定性回放
→ 同信息、同分母、同成本、同风险的轨迹
→ 另行授权的评估
→ 反馈到理论，但不改写历史证据
```

核心原则是：

> 交易系统可以保留多条市场假说，但证据本身不能有多套历史。未知必须保持未知，修订必须从真实可得时点生效，缺口必须进入分母，任何候选都不能通过重新签名自己的声明取得权威。
