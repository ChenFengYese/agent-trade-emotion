# 72 小时纸面交易中文记录附加要求 v2

本附加要求只负责把已经提交的纸面交易工件导出为中文审计文档，不改变冻结理论、行情分析、交易决策、风险门、纸面撮合或 72 小时运行状态。v2 在 v1 的决策轨迹之上，新增标准账户、逐仓持仓和完整历史交易信息。

每次自动任务唤醒时必须：

1. 在创建新周期前，执行：

   ```bash
   /opt/homebrew/bin/python3.12 -m trade_system.theory_paper.zh_record \
     --run-dir .runtime/theory-paper-v1/current --all
   ```

   这一步补齐并校验所有已提交周期的 v2 中文文档。没有已提交周期时可以继续正常首轮流程。

2. 当轮 `theory-paper-submit` 成功后，再次执行同一命令。只有命令退出码为 0、`schema_version=theory-paper-zh-audit-record.v2`、返回周期数等于已提交决策周期数，且每条记录均给出路径和 SHA-256，才算当轮记录完成。

3. 每轮文档写入：

   `.runtime/theory-paper-v1/current/reports/zh/`

   文件名使用该轮实际执行提交时间的北京时间、周期 ID、Agent/轮次编号和 `_zh_v2.md` 后缀；不得用自动任务唤醒时间冒充决策时间，也不得覆盖 v1 或任何既有 write-once 文档。

4. 每轮决策与理论记录必须完整覆盖：

   - 冻结输入、数据质量、全部多尺度指标和 `D/L/C/F/R/K` 测量；
   - 结构位置、全部候选几何、全部竞争路径、支持与冲突证据；
   - 冻结 thesis、替代假说、支持/否证谓词、到期与下一观测；
   - 当前行动或不行动、风险门和机会成本；
   - 盘中撮合、情绪扰动、Agent 动作及逐项执行回执；
   - 冻结理论版本与摘要、理论章节映射、公开理论/数据来源及适用边界；
   - 事务摘要、账本事件、原始工件路径、文件 SHA-256 与事务绑定摘要。

5. 每轮账户总览必须输出：

   - 快照时间、账户模式、纸面边界和 USDT 名义口径；
   - 初始权益、当前权益、现金、总净盈亏和账户累计收益率；
   - 未实现盈亏、已实现毛/净盈亏、手续费和资金费模拟状态；
   - 当前持仓价值、挂单名义、总名义、毛杠杆、回撤；
   - 持仓开放风险、持仓加挂单风险及成本价至止损口径。

6. 每个 lot 必须逐项输出：

   - lot ID、标的、开仓方向、状态、来源、归因和父假说；
   - 精确开仓时间、平仓时间、持有时间和精确开仓价格；
   - 初始基础资产数量、剩余基础资产数量、入场名义 USDT；
   - 对应决策时点的标记价格和标记时间、当前持仓价值 USDT；
   - 未实现价格盈亏、价格收益率、毛/净已实现盈亏、累计净盈亏和累计净收益率；
   - 入场费、剩余入场费、退出费、MFE 和 MAE；
   - 止损触发价、预计止损成交价、止损保护基础数量、止损触发名义 USDT、止损后预计净盈亏；
   - 止盈触发价、预计止盈成交价、止盈保护基础数量、止盈触发名义 USDT、止盈后预计净盈亏；
   - 当前开放风险、目标收益、净盈亏比、初始风险和保护激活时间。

   未实现盈亏必须使用运行时相同口径：方向 × 剩余数量 ×（标记价−开仓价），不得预扣尚未发生的退出费。逐 lot 合计必须与组合 `unrealized_pnl_usdt` 核对并报告差额。

7. 历史交易信息必须完整输出：

   - 所有 lot，包括已开、部分平仓和已平仓状态；
   - 所有订单，包括创建/激活/取消时间、方向、类型、价格、初始/剩余数量、初始/剩余名义、reduce-only、止盈止损、归因、父假说、状态和取消原因；
   - 所有成交，包括成交时间、方向、数量、价格、名义、手续费、滑点假设与成本、原因、归因、订单、开仓 lot、平仓明细、同 K 歧义和拒绝超额数量；
   - 当前周期全部 Agent 动作与执行回执；
   - 原始 `lots/orders/fills` 对象附录，保留表格未展开的授权和内部状态字段。

   没有订单、成交或某字段未知时必须明确写“无”或“未知”。用户提供的初始外生仓位可以输出精确开仓价和数量，但不得伪造不存在的历史成交回执。

8. “完整推理链路”按可审计的“输入—规则—判断—动作—结果—来源”记录；不得声称、伪造或要求模型私有的逐 token 隐藏思维。未写入冻结工件的理由必须标为不可追溯，不能事后补造。

9. 中文文档是 write-once sidecar。若同名文档已存在，只有内容逐字一致才允许成功；内容不一致、盈亏核对不通过、摘要不匹配、账本无对应提交事件或任一原始工件缺失时必须失败关闭并在当前任务中报告，不得修改历史交易工件来适配报告。

10. 中文记录导出失败不能用于改变市场判断或重写已提交决策；修复范围只限记录导出器或自动任务提示词。
